# Десктопное приложение

Русский | [English](desktop.md)

Десктопное приложение - это окно демона на macOS, Windows и Linux. Это оболочка Tauri 2 с
фронтендом на Svelte 5, и она никогда не говорит с демоном напрямую: каждый вызов идет через Rust,
который открывает локальный эндпоинт и проксирует запрос.

```
Svelte 5 frontend        stores, screens, i18n
  Connect client         protobuf over Tauri IPC
Rust shell (src-tauri)   daemon supervision, local API proxy, tray, login item
  HTTP/2 h2c             unix socket or named pipe
unisond                  the core
```

## Фронтенд

`desktop/src` - это Svelte 5 с TypeScript, собираемый Vite. Точек входа две, потому что приложение
открывает второе небольшое окно для вопросов:

| Точка входа | Монтирует | Назначение |
|-------|--------|---------|
| `src/main.ts` | `App.svelte` | главное окно |
| `src/prompt.ts` | `PromptWindow.svelte` | вопрос поверх других окон |

| Область | Путь |
|------|------|
| Хранилища | `src/lib/stores/*.svelte.ts` |
| Клиент API и сгенерированный protobuf | `src/lib/api` |
| Экраны | `src/lib/screens` |
| Склейка оболочки | `src/lib/*.ts` (tray, notify, files, login, events, network, policy) |
| Переводы | `src/lib/i18n` (английский и русский) |

Хранилища - это классы рун Svelte 5: `daemon`, `dashboard`, `history`, `requests`, `pairing`,
`prompts`, `transfers`, `notifications`, `confirmation`, `theme`. Хранилище владеет своими данными и
вызывает API; экран его отрисовывает и отправляет действия.

Настройки > Общие > Файл настроек экспортирует документ настроек демона вместе с темой и элементом
входа в `app.desktop`, а импорт применяет документ, а затем локальные настройки. Формат описан в
разделе [Файл настроек](settings-file.ru.md).

`daemon.svelte.ts` опрашивает `GetStatus` каждые 5 секунд, следит за `WatchEvents` и переоткрывает
поток через 3 секунды, когда он падает, держит последние события и передает состояние трея при
каждом обновлении. Пока демон не отвечает, хранилище опрашивает его каждые 300 мс до 10 секунд, а
экраны показывают спиннер, чтобы окно, открытое до запуска демона, не выглядело сломанным. Неудачный
запуск показывается сразу, не дожидаясь таймаута.
Уведомления подписываются до запуска демона, потому что их кнопки действий
нужно зарегистрировать до того, как придет первое.

Слой i18n выбирает `en` или `ru` по локали браузера. Встроенный текст не переводится: сообщения,
которые приходят от демона, показываются как есть.

Экран настроек делит разделы на пять вкладок: в Общих имя устройства, внешний вид, обзор, запуск,
журнал приложения и файл настроек, в Буфере обмена пауза, подтверждение новых устройств, параметры
отслеживания и сроки хранения истории, в Файлах папка полученных файлов и сетевая политика, в Сети
поиск друзей, переключатель удаленных настроек и ретранслятор, в Приватности диагностика и предупреждение о
хранилище ключей. Состояние демона и уведомления остаются над вкладками, поэтому потеря связи видна
с любой вкладки. Экран открывается на Общих.

### Обзор

`Dashboard.svelte` - первый раздел боковой панели и экран, который открывается вместе с окном. Он
показывает новые элементы истории на трех вкладках: изображения сеткой миниатюр, файлы списком с
именами и размерами, текст фрагментами. Миниатюры приходят от демона, поэтому страница сама не
декодирует изображения. Число элементов на вкладке - локальная настройка (`unison.dashboard.limit` в
`localStorage`); в разделе Настройки > Общие предлагаются 6, 12, 24 и 48, по умолчанию 12. Клик открывает
просмотр с изображением в полном размере, текстом или списком файлов. На macOS изображение или
файл можно перетащить из окна; текст перетащить нельзя.

Хранилище `dashboard` следит за событиями демона и перезагружает вкладки, ограничивая их заданным
числом. У экрана истории свое хранилище, и обзор на него не влияет.

## Прокси локального API

Демон слушает unix-сокет или named pipe, а webview не умеет ни того, ни другого. Фронтенд
использует клиент Connect с собственным `fetch`, который отправляет сериализованный запрос по
Tauri IPC:

1. `invoke("api_call", {service, method, body})` для унарного вызова;
2. `invoke("api_stream", {id, service, method, body, onChunk})` с каналом Tauri для серверного
   потока и `api_stream_cancel`, чтобы его остановить.

`desktop/src-tauri/src/proxy.rs` открывает эндпоинт и выполняет рукопожатие hyper HTTP/2 открытым
текстом, затем отправляет запрос с заголовками Connect:

| Свойство | Значение |
|----------|-------|
| URI | `http://unison/<service>/<method>` |
| Content type унарного вызова | `application/proto` |
| Content type потока | `application/connect+proto` |
| Таймаут запроса | 30 с |
| Лимит ответа | 16 MiB |

Имена сервиса и метода проверяются по белому списку символов, а эндпоинт проверяется до
использования: каталог не должен быть доступен на запись другим пользователям, сокет должен
принадлежать текущему пользователю, и только он должен иметь к нему доступ, а symlink
отклоняется. Это повторяет проверку клиента на Go, поэтому подмененный эндпоинт недостижим и через
приложение.

`streams.rs` держит реестр потоков на каждый webview. Перезагрузка отменяет все потоки этого
webview, поэтому исчезнувшая страница не держит открытым поток `WatchEvents`.

## Оболочка на Rust

| Модуль | Ответственность |
|--------|----------------|
| `lib.rs` | сборщик Tauri, окно, список команд |
| `daemon.rs` | разрешение эндпоинта и наблюдение за демоном |
| `agent.rs` | элемент входа в систему: `SMAppService` на macOS, ключ `Run` на Windows, user unit на Linux |
| `proxy.rs`, `streams.rs` | мост к локальному API |
| `tray.rs` | иконка трея, ее меню и выбор файлов |
| `prompt.rs` | окно вопроса без рамки |
| `files.rs` | показать файл в каталоге, открыть файлы |
| `dragout.rs` | подготовить копии элемента и начать системное перетаскивание из окна |
| `journal.rs` | журнал приложения оболочки и его экспорт |
| `settings.rs` | документ настроек оболочки, который читается и пишется в выбранном пользователем файле |
| `observability.rs` | отчеты об ошибках оболочки |
| `redact.rs` | пути, удаляемые из отчетов и журналов |
| `i18n.rs` | локаль сообщений оболочки |

### Наблюдение за демоном

`daemon.rs` разрешает эндпоинт так же, как клиент на Go: сначала `UNISON_LOCAL_API`, затем путь
платформы по умолчанию, на Linux это `$XDG_DATA_HOME/unison`.

1. опросить эндпоинт до 500 мс;
2. на Linux попросить менеджер служб запустить user unit командой `systemctl --user start
   unisond.service` и ждать ответа до 10 секунд. Сеанс без менеджера служб переходит на бинарник
   приложения;
3. когда элемент входа macOS включен, подождать до 3 секунд, пока launchd запустит демон;
4. иначе запустить упакованный `unisond` рядом с приложением и ждать до 10 секунд ответа, опрашивая
   каждые 200 мс.

Состояние отдается как `running`, `offline` или `failed` с причиной, и фронтенд его показывает. На
Linux причина неудачного запуска называет `journalctl --user -u unisond -n 50`: подробности лежат
в журнале юнита. Демон, который приложение запустило само, останавливается через `SIGTERM`, когда
его подхватывает элемент входа, поэтому на каталог данных работает только один экземпляр. В
отладочной сборке бинарник берется из `bin/unisond`, `UNISON_DAEMON_BIN` его переопределяет, а юнит
не используется.

### Окно и трей

Закрытие окна его скрывает: приложение продолжает работать в трее, пока не выбран `Quit Unison`.
Демон в любом случае переживает приложение.

Меню трея несет статус, варианты паузы (5 минут, 1 час, до выключения, выключено), последние
элементы буфера обмена, подменю, которое отправляет файлы на устройство, `Open` и `Quit`.
Фронтенд передает состояние через `set_tray_state`, поэтому трей и окно никогда не расходятся.
Действие меню доставляется фронтенду как событие `tray-action`.

macOS и Windows открывают меню по клику на иконку трея. Linux показывает иконку через хост
уведомлений о состоянии рабочего стола, который сеанс GNOME предоставляет расширением
AppIndicators; клик там открывает меню и никогда не доходит до приложения, поэтому каждое действие
- это пункт меню. Иконка - цветная иконка приложения, потому что монохромный глиф не виден на
темной панели. Когда в сеансе нет такого хоста, приложение запускается без иконки, а закрытие окна
завершает его, поэтому окно никогда не остается работающим и недостижимым.

Уведомления приходят от системной службы уведомлений. Их кнопки регистрируются до первого
уведомления и сообщают `accept`, `decline`, `apply`, `show-in-folder` и `open`. Рабочий стол,
который не показывает кнопки, сообщает клик по самому уведомлению как `tap`, и приложение поднимает
свое окно, где ожидает запрос.

Окно вопроса - это второй webview без рамки, 360 на 150 пикселей, в правом верхнем углу, поверх
других окон и без записи в панели задач. Оно спрашивает, применить ли элемент буфера обмена или
принять файлы, и его можно отложить кнопкой `Later`.

### Перетаскивание элементов наружу

На macOS, Windows и Linux изображение или файл из обзора можно перетащить из окна. Когда нажатие
становится перетаскиванием, фронтенд запрашивает у `drag_staging_dir` новый каталог в кэше
приложения (`drag/`) и загружает туда содержимое через `FetchHistoryItem`. Когда копии записаны,
`start_file_drag` получает их пути, и бэкенд в `dragout/` начинает системный сеанс перетаскивания с
`DragItem::Files` и `DragMode::Copy`. Обычный клик ничего не готовит и открывает просмотр. Несколько
файлов одного элемента перетаскиваются вместе. Превью перетаскивания - первое подготовленное
изображение или иконка приложения.

Бэкенды различаются тем, что начинает сеанс: macOS запускает `NSDraggingSession` и возвращает
управление, пока пользователь еще тащит, Windows выполняет OLE `DoDragDrop`, а Linux назначает
источник перетаскивания окну GTK `ApplicationWindow`, которое Tauri отдает через `gtk_window()`.
Бэкенду Linux нужна нажатая основная кнопка мыши к моменту, когда команда доходит до главного
потока, поэтому копии должны быть готовы, пока пользователь держит указатель.

`start_file_drag` канонизирует каждый путь и принимает только файлы внутри каталога кэша, поэтому
окно не может отдать другому приложению произвольный файл пользователя. Каталоги подготовки доступны
только пользователю. Копии остаются после сброса: терминал вставляет путь копии, а инструмент
командной строки может прочитать содержимое позже. При запуске оболочка удаляет каталоги подготовки
старше 24 часов.

Контекстное меню элемента использует ту же подготовку для `Send`: копии уходят одному устройству в
сети через `SendFiles`. `Copy` подготовку не использует: он вызывает `CopyHistoryItem`, поэтому
демон пишет элемент в буфер обмена с отметкой собственной записи. Копия не объявляется новым
элементом и не попадает на другие устройства. `Delete` удаляет элемент из истории на всех личных
устройствах.

## Упаковка

`tauri.conf.json` держит общую конфигурацию: идентификатор `app.unison`, минимальный macOS 13,
файл entitlements, ключи `Info.plist` и plist LaunchAgent как упакованный файл. Версия берется из
`VERSION` и передается через `--config '{"version": ...}'` при сборке.

| Платформа | Конфигурация | Сборка |
|----------|---------------|-------|
| macOS | `tauri.conf.json` | `.app` с демоном и LaunchAgent, затем подписанный и нотаризованный DMG |
| Windows | `tauri.windows.conf.json` | установщик NSIS с демоном как внешним бинарником |
| Linux | `tauri.linux.conf.json` | `.deb` с демоном, CLI и user unit, собирается в контейнере целевой платформы |

Окно macOS без заголовка, а светофоры расположены над боковой панелью. Windows и Linux сохраняют
рамку рабочего стола, поэтому окно Linux задает ее в своем файле конфигурации.

Приложение объявляет только entitlements hardened runtime
`com.apple.security.network.client` и `com.apple.security.network.server`, а также типы сервисов
Bonjour для трех сервисов mDNS.

Плагина обновлений и плагина единственного экземпляра нет. Второй экземпляр отклоняет демон, а не
оболочка, и пользователь запускает второй демон со своим каталогом данных.

## Разработка

`just desktop-dev` запускает Vite на `127.0.0.1:1420` с горячей перезагрузкой и стартует оболочку
Tauri, которая открывает демон из дерева исходников. `just desktop-build` пишет сборку в
`desktop/src-tauri/target/release/bundle`, `just desktop-test` запускает компонентные тесты, а
`just lint-desktop` запускает ESLint, Prettier и `svelte-check`.

Приложению Linux нужны WebKitGTK и тулчейн платформы, поэтому `just package-linux` собирает его и
пакет в контейнере linux/amd64 на любой машине. Демон и CLI собираются кросс-компиляцией.

### Журнал приложения

Настройки > Общие > Журнал приложения включают журнал для поддержки. Демон отмечает его файлом
`logs/journal.on` в каталоге данных платформы, это `~/Library/Application Support/Unison` на macOS,
`%LOCALAPPDATA%\Unison` на Windows и `$XDG_DATA_HOME/unison` на Linux; он пишет
`logs/journal.log`, а оболочка пишет рядом `logs/app.log`. Оба файла ротируются и используют один
формат строки: время в UTC с миллисекундами, уровень, сообщение и атрибуты. Оболочка проверяет
маркер для каждой записи, поэтому переключатель применяется без перезапуска, и записывает только
ошибки старта демона, сбои команд оболочки, неудачные копирование или отправку и паники.

- Экспорт - это текстовый файл `unison-log-YYYYMMDD-HHMMSS.log`. В заголовке версии приложения и
  демона, версия системы, устройство, состояние сети, адреса и все настройки без секретов;
  `downloads_dir` всегда выглядит как `[path]`.
- Копирование и отправка всегда включают все уровни, в том числе DEBUG, а уровень на странице
  меняет только то, что показывает окно.
- Файл пишется во временный каталог и открывается в системной шторке macOS. Если шторку показать
  нельзя, приложение спрашивает, куда сохранить файл, и показывает его в файловом менеджере.
