# Android

Русский | [English](android.md)

На Android ядро работает внутри процесса приложения. Демона и локального сокета там нет: ядро на
Go встроено в приложение как AAR, foreground-сервис держит его живым, а UI вызывает его в процессе.

```
app (Kotlin, Compose)
  CoreClient      local API calls and events
  UnisonService   foreground service, owns the core
  Clipboard       reader, writer, tiles, share target
  BridgeService   AIDL interface for keyboards
core.aar          the Go core, built with gomobile
```

## Модули

| Модуль | Назначение |
|--------|---------|
| `android/app` | приложение: UI, сервис, буфер обмена, плитки, мост-сервис |
| `android/bridge-aidl` | замороженный контракт AIDL, публикуемый как артефакт Maven |
| `android/core/core.aar` | привязка gomobile для `mobile/`, генерируется и не коммитится |

`just aar` связывает `mobile/` для `arm64-v8a`, `armeabi-v7a` и `x86_64` на API 29 и пишет
`android/core/core.aar`, от которого модуль приложения зависит как от локального файла.
`android-build` сначала запускает `aar`, потому что без него приложение не собирается.

`just proto-android` генерирует lite-классы Java для `unison.local.v1` и `unison.mobile.v1` в
`android/app/src/main/java`; запускайте его после изменения proto-файла и коммитьте результат.

## Фасад на Go

`mobile/` - это узкий байтовый API для gomobile:

| Функция | Назначение |
|----------|---------|
| `Start(cfg, platform)` | запускает ядро с сериализованной конфигурацией |
| `Stop()` | останавливает ядро |
| `Version()` | версия, вложенная при сборке |
| `Call(req)` | один метод локального API, ответ - сериализованный ответ |
| `SubmitClip(item)` | отправляет содержимое буфера обмена, прочитанное приложением |
| `SubmitFile(meta, fd)` | берет открытый дескриптор, сохраняет и предлагает файл |
| `AddPeerCandidate(service, addr, txt)` | сообщает об обнаруженном экземпляре |
| `NetworkChanged(state)` | обновляет состояние сети |

Запросы и ответы - это protobuf-сообщения из `proto/unison/mobile/v1`, который оборачивает
локальный API. `Call` покрывает те же методы, что API демона, кроме `WatchEvents` (события приходят
через колбэк) и нескольких вызовов, которые мобильный UI не использует. Запрос ограничен 1 MiB и
отвечается за 30 секунд, кроме `FetchHistoryItem`, которому дается 30 минут.

`Platform` - интерфейс, который реализует сторона Kotlin. Каждый колбэк выполняется в горутине
ядра:

| Колбэк | Назначение |
|----------|---------|
| `OnEvent` | одно сериализованное событие |
| `WriteClipboard` | записать входящий элемент в системный буфер обмена |
| `OpenBlobSink` | вернуть дескриптор для входящего файла |
| `KeystoreWrap`, `KeystoreUnwrap` | защитить и прочитать секрет через Android Keystore |
| `Announce` | опубликовать или снять объявление mDNS |

Фасад держит одно ядро на процесс: второй `Start` падает, а `Stop` ждет до десяти секунд.

## Порты на Android

Фасад поставляет все четыре порта, поэтому ядро не знает, что работает в приложении:

- **Буфер обмена.** Ядро не может следить за буфером обмена в фоне, поэтому `Watch` ничего не
  сообщает и никогда не падает. Приложение читает буфер обмена, когда у него есть фокус, и вызывает
  `SubmitClip`; входящие элементы попадают в системный буфер обмена через `Platform.WriteClipboard`.
- **Обнаружение.** Колбэк платформы публикует и ищет mDNS через `NsdManager`. На Android есть только
  сервисы `main` и `pairing`: устройство Friends не может открыть сессию с Android, поэтому сервис
  `friends` отклоняется.
- **Хранилище ключей.** Ядро хранит свои ключи в `<data dir>/keys` как файлы, и каждый файл
  обернут ключом AES-256-GCM, который лежит в Android Keystore под алиасом `unison.master`. Формат
  файла - байт версии, 12-байтовый IV и шифртекст с тегом, а AAD - байт версии. Мастер-ключ никогда
  не покидает хранилище, поэтому перезапуск процесса сохраняет тот же ID устройства, а копию
  каталога приложения прочитать нельзя.
- **Часы.** Системные часы.

## Сервис

`UnisonService` - это foreground-сервис типа `connectedDevice`. Он владеет ядром на время жизни
приложения:

- запускает ядро с каталогом файлов и именем устройства из настроек и останавливает оставшееся
  ядро перед запуском нового;
- останавливает ядро, когда сервис уничтожается;
- показывает имя устройства и число устройств онлайн в постоянном уведомлении на канале
  `service`;
- обрабатывает действия этого уведомления (`Send clipboard`, скачивание, применение, отмена) и
  уведомлений запросов.

Сервис `START_STICKY`, переживает удаление задачи и перезапускается после `BOOT_COMPLETED` для
режимов, которые это разрешают.

| Режим работы | Поведение |
|----------------|----------|
| `always` | ядро работает с загрузки и из приложения |
| `wifi_only` | ядро работает на Wi-Fi или Ethernet, иначе ждет |
| `app_open` | сервис работает, пока активность на переднем плане |

Режим хранится в shared preferences `unison.settings` под `service.operating_mode`, а имя
устройства - под `device.name`. Ядро читает состояние сети из `NetworkMonitor`.

| Канал | Важность | Содержимое |
|---------|------------|---------|
| `service` | низкая | постоянный статус с действием отправки |
| `transfers` | низкая | прогресс исходящих передач |
| `requests` | высокая | предложение, ожидающее решения |
| `confirmations` | высокая | удержанный элемент буфера обмена |
| `clipboard` | низкая, без звука | элемент, пришедший только как метаданные |

## Буфер обмена

Система разрешает приложению писать в буфер обмена в фоне, но не читать его, поэтому два
направления разделены.

**Чтение.** `SendClipboardActivity` - прозрачное окно, которое открывают плитка быстрых настроек
`Send clipboard`, действие уведомления и главный экран. Оно читает буфер обмена, когда окно
получает фокус, отправляет содержимое через `SubmitClip` и закрывается. Clip с
`EXTRA_IS_SENSITIVE` никогда не читается; clip без текста сообщается как неподдерживаемый. Главный
экран также предлагает буфер обмена при получении фокуса, когда его хеш отличается от
`clipboard.last_hash`, поэтому только что пришедшее содержимое не отправляется обратно к
источнику.

**Запись.** `UnisonService` пишет входящие элементы через `Platform.WriteClipboard`. Простой текст
становится `ClipData.newPlainText`, текст с HTML - `ClipData.newHtmlText`, оба с меткой `Unison`
и тегом ID элемента. Изображение пишется как URI `FileProvider` под `cache/clipboard` authority
`app.unison.files`; старые файлы вычищаются.

**Пауза.** `PauseClipboardTile` открывает диалог с вариантами 5 минут, 1 час или до выключения, и
пауза живет в ядре, поэтому покрывает оба направления.

## Файлы

Входящий файл пишется через сток платформы: `BlobSink` создает запись в `Download/Unison` через
`MediaStore`, пишет байты через pipe и в конце помечает запись завершенной. Предпочтителен каталог,
который пользователь выбрал системным пикером; Unison получает доступ к этому каталогу и ни к чему
больше, поэтому приложение не просит разрешение на хранилище. Несовпадение размера отбрасывает
запись.

Скачивание из истории сначала готовит файл в кеше, затем копирует его в то же место и отменяет
свое уведомление.

## Приемник Share

`ShareActivity` - это цель отправки для других приложений. Она принимает потоки из URI
`content://` и текст, показывает для обоих устройства Personal онлайн, а для файлов - устройства
Friends, и передает каждый файл ядру через `SubmitFile`. Она перечитывает содержимое, когда приходит
новая отправка, пока она открыта, и заново перечисляет устройства, когда возвращается на передний
план. Лимит - 32 файла.

## Спаривание

Экран `Add device` открывает окно спаривания и показывает QR-код. Код можно прочитать кнопкой
`Scan a code` или системной камерой, которая открывает ссылку `unison://pair` в Unison. Ссылка
никогда не спаривает сама по себе: приложение спрашивает еще раз и называет роль, которую получит
другое устройство.

## Мост для клавиатур

Приложение отдает интерфейс AIDL приложениям-клавиатурам, подписанным тем же ключом. Контракт лежит
в `android/bridge-aidl` и заморожен: новые методы только добавляются в конец, а вызывающая сторона
читает `protocolVersion()` до того, как использовать неизвестные ей методы.

| Свойство | Значение |
|----------|-------|
| Пакет | `app.unison` |
| Действие привязки | `app.unison.bridge.BIND` |
| Сервис | `app.unison.service.BridgeService` |
| Разрешение | `app.unison.permission.BRIDGE` (signature) |
| Версия протокола | 2 |

Сервис проверяет при каждом вызове, что вызывающая сторона - это само приложение или пакет,
подписанный одним из его сертификатов. Текст и HTML едут как parcel; бинарник передается как pipe,
до 16 MiB. Публикация сообщает результат через `IPublishCallback`, а зарегистрированный слушатель
получает входящие элементы и состояние паузы.

`just bridge-publish` публикует модуль как `app.unison:bridge-aidl:<version>` в локальный
репозиторий Maven, который репозиторий клавиатуры добавляет как репозиторий.

## Сборка

| Рецепт | Результат |
|--------|--------|
| `just aar` | `android/core/core.aar` |
| `just android-build` | отладочный APK |
| `just deploy-android` | устанавливает APK по USB |
| `just android-lint` | Android lint |
| `just bridge-publish` | артефакт AIDL |

Приложение нацелено на API 37, работает с API 29 и объявляет `ACCESS_LOCAL_NETWORK`, который нужен
приложениям с target API 37, чтобы достать до локальной сети. `versionName` берется из `VERSION`.

## Отчеты об ошибках

`diagnostics/Diagnostics` оборачивает Sentry для приложения с тегом компонента `android`. DSN
приходит из сборки, отчеты выключены, пока пользователь не даст согласие, и отправляются только
необработанные исключения и ANR: breadcrumbs, трейсинг и персональные данные выключены, а пути
вычищаются.

## Журнал приложения

Пользователь включает журнал приложения в Настройках > Журнал приложения. Пока он включен,
оболочка дописывает свои записи в `logs/app.log` каталога данных, а ядро пишет
`logs/journal.log`; оба файла ротируются и хранят резервные копии, а `logs/journal.on`
существует ровно столько, сколько журнал включен, поэтому переключатель применяется без
перезапуска сервиса. Записи используют тот же формат строки, что и на других платформах, а
абсолютные пути становятся `[path]`.

Копирование и отправка собирают один текстовый файл из заголовка и объединенных записей обоих
файлов и их резервных копий; живая страница читает только текущие файлы. В заголовке версии
приложения и ядра, версия ОС, устройство, состояние сети, адреса слушателя и настройки, где
`downloads_dir` показан как `[path]`; токены ретранслятора и ключи не попадают никогда. Уровень
на странице фильтрует только живой вид: экспорт всегда содержит и записи debug.
