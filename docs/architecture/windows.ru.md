# Windows

Русский | [English](windows.md)

На Windows демон работает как `unisond.exe` рядом с приложением, как внешний бинарник сборки. У
него нет ни окна, ни консоли, он держит секреты под защитой DPAPI, следит за буфером обмена и
отдает локальный API на named pipe.

```
%ProgramFiles%\Unison\
  Unison.exe          Tauri shell, the window
  unisond.exe         the daemon, GUI subsystem
```

## Перетаскивание файлов из окна

На Windows изображение или файл из обзора можно перетащить из окна. Приложение складывает
содержимое элемента в каталог своего кэша и начинает нативное OLE-перетаскивание копий, сразу
нескольких файлов одного элемента. Превью перетаскивания - первое подготовленное изображение или
иконка приложения. Копии остаются 24 часа, поэтому терминал, получивший путь после сброса, все еще
находит содержимое. Из окна перетаскиваются только файлы ниже каталога подготовки.

## Порты платформы

`platform/windows` дает два из четырех портов и собирается на любом хосте, поэтому
`just vet-windows` проверяет его с любой машины. Вне Windows операции возвращают `ErrUnsupported`.

### Хранилище ключей

`platform/windows/keystore` держит каждый секрет в своем файле, защищенном DPAPI для текущего
пользователя Windows.

- имя секрета отображается в путь файла с суффиксом `.bin`, поэтому `identity/ed25519-seed`
  становится `identity/ed25519-seed.bin` внутри `<data dir>/keys`;
- файлы заменяются атомарно через временный файл и переименование;
- необязательное значение энтропии, переданное в конструктор, подмешивается в защиту;
- защищенные блобы принадлежат записавшему их аккаунту, поэтому другой аккаунт или другая машина
  прочитать их не могут.

Тесты вызывают настоящий DPAPI и идут только на Windows.

### Буфер обмена

`platform/windows/clipboard` использует Win32 через `golang.org/x/sys/windows`, без cgo. Окно
только для сообщений на закрепленном потоке ОС получает `WM_CLIPBOARDUPDATE` через
`AddClipboardFormatListener`, поэтому наблюдатель не опрашивает.

- чтение покрывает `CF_UNICODETEXT`, `HTML Format`, PNG и device independent bitmaps, а также
  список перетащенных файлов;
- заголовок CF_HTML несет байтовые смещения документа и фрагмента, и записи снова заворачивают
  фрагмент в такой заголовок;
- изображение пишется как PNG плюс bitmap для приложений без поддержки PNG, а файлы - как список
  перетащенных файлов;
- содержимое с `ExcludeClipboardContentFromMonitorProcessing` или с
  `CanIncludeInClipboardHistory` либо `CanUploadToCloudClipboard` в 0 сообщается как
  чувствительное, и его полезная нагрузка никогда не читается;
- собственные записи несут `Unison.Origin`;
- буфер обмена, который держит открытым другое приложение, повторяется до одной секунды.

Интеграционные тесты находятся под build-тегом `clipboardtest` и идут на Windows через
`just test-clipboard`.

## Демон

Демон использует подсистему GUI и стартует без консоли, поэтому файл лога - единственный вывод. Его
каталог данных - `%LOCALAPPDATA%\Unison`, и он держит базу, blob-хранилище, логи и каталог `keys`.
Эндпоинт - named pipe `\\.\pipe\unison-<user-sid>`, а собственный каталог данных получает имя
pipe, производное от его пути. `--endpoint` и `UNISON_LOCAL_API` его переопределяют.

Поскольку каталог установки и данные пользователя независимы, установка для всех пользователей
все равно держит секреты и базу отдельно для каждого пользователя.

## Упаковка

`just package-windows` собирает демон под архитектуру хоста, кладет его в
`desktop/src-tauri/binaries/unisond-<target triple>.exe` и собирает установщик NSIS через
`tauri build --bundles nsis`. Результат - `packaging/windows/build/Unison-<version>-setup.exe`, а
версия берется из `VERSION`.

Конфигурация сборки для Windows лежит в `desktop/src-tauri/tauri.windows.conf.json`, и Tauri
сливает ее с общей конфигурацией. Упаковщик кладет демон рядом с `Unison.exe`.

### Установка

Установщик ставит приложение для всех пользователей в `%ProgramFiles%\Unison` по умолчанию,
позволяет выбрать другой каталог и один раз просит повышение прав. Правилу брандмауэра нужно
повышение прав, поэтому установка для машины держит правило там же, где файлы.

Хуки в `desktop/src-tauri/installer-hooks.nsh` делают четыре вещи:

| Шаг | Действие |
|------|--------|
| перед копированием | останавливает работающий `unisond.exe` |
| после копирования | пишет запись автозапуска и добавляет правило брандмауэра |
| перед удалением | останавливает `unisond.exe`, удаляет запись автозапуска и правило |
| после удаления | удаляет `%LOCALAPPDATA%\Unison`, когда выбрана опция удаления данных приложения |

- **Брандмауэр.** Правило с именем `Unison daemon` разрешает `unisond.exe` в профилях private и
  domain, только UDP. Профиль public остается закрытым, поэтому устройство в публичной сети и не
  достучится до демона, и не будет им найдено. При переустановке старое правило сначала удаляется.
- **Запись автозапуска.** `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\Unison` запускает
  `unisond.exe` при входе пользователя, который запускал установщик, поэтому повторный вход
  запускает демон без приложения. Переключатель автозапуска в настройках пишет и удаляет то же
  значение, а деинсталлятор его удаляет. Изменение переключателя действует только на следующий
  вход; работающий демон оно не трогает.

Деинсталлятор не трогает каталог данных, если не использована его опция удаления данных
приложения.

### Установка демона из приложения

Приложение само ставит демон, когда установки нет, поэтому починка не требует терминала. Окно
показывает "Установить службу" под состоянием демона, как только демон не отвечает и установки
нет; на установленном и работающем приложении и на других платформах кнопки нет.

Приложение один раз запускает `Unison.exe --install-daemon` с запросом повышения прав. Скрытый
режим выходит до старта окна, копирует демон, пишет запись автозапуска и добавляет правило
брандмауэра, после чего приложение запускает демон от имени пользователя.

- **Источник.** `unisond.exe` рядом с приложением либо `UNISON_DAEMON_BIN` для dev-сборки. Без
  источника приложение ничего не меняет и говорит причину; скрытый режим принимает еще
  `--daemon-source=<path>` для пути, который разрешило приложение.
- **Каталог.** `%ProgramFiles%\Unison`, каталог установки по умолчанию. Приложение, которое уже
  запущено оттуда, ставит в свой каталог, а приложение, поставленное установщиком в другой каталог,
  все равно ставит демон в `%ProgramFiles%\Unison` и запускает его оттуда, потому что повышенный
  процесс не должен писать в каталог, выбранный вызывающим пользователем. В пользовательский
  каталог приложение не ставит никогда.
- **Повышение прав.** Один запрос покрывает копию, запись и правило. Отказ в запросе ничего не
  меняет, а окно показывает причину на месте.
- **Демон.** Демон работает от имени вошедшего пользователя и никогда от имени повышенного
  процесса, потому что ему нужны буфер обмена и секреты DPAPI этого пользователя. Скрытый режим
  пишет файлы, демон запускает приложение, а повтор установки работающий демон не трогает.
- **Отчет.** Скрытый режим пишет свои шаги в файл, путь к которому передает приложение, и
  приложение записывает их в свой лог. У повышенного процесса нет консоли, поэтому файл -
  единственный канал причины.

Запись автозапуска принадлежит той учетной записи, от имени которой работает повышенный процесс.
Администратор, который подтвердил запрос другими учетными данными, пишет запись для них, а
текущий пользователь не получает ничего; штатный способ установки для всех - установщик.

Установщик остается штатным способом установки и обновления Unison. Имена у него те же, и тест
сравнивает их с константами приложения.

### Обновление из приложения

Апдейтер читает релизы GitHub и скачивает `unison-v<version>-windows.exe`, установщик NSIS релиза. Он
проверяет подпись Ed25519 и хеш SHA-256 файла до любого шага установки. Автоматические проверки по
умолчанию выключены, и обзор предлагает релиз, когда он найден.

Установщик заменяет работающие бинарники, поэтому приложение не может запустить его напрямую:

- Приложение штатно останавливает демон, ждет его named pipe до пяти секунд и завершает демон,
  который не подчинился, командой `taskkill /F /IM unisond.exe`.
- Приложение копирует `Unison.exe` в каталог своего кэша и запускает копию без повышения прав. Копия
  ждет выхода приложения, запускает установщик с одним запросом повышения прав и параметром
  `/S /D=<каталог установки>`, поэтому выбранный каталог установки сохраняется.
- Установщик снова пишет запись автозапуска и правило брандмауэра. Если пользователь выключил
  "Запускать при входе", помощник удаляет запись после установки, поэтому обновление не включает ее
  обратно.
- После успешной установки помощник запускает `<каталог установки>\Unison.exe` без повышения прав,
  поэтому приложение и демон работают с токеном вошедшего пользователя и сохраняют доступ к буферу
  обмена и секретам DPAPI.
- Если пользователь отменяет запрос повышения прав, ничего не меняется: помощник записывает причину в
  лог приложения и снова запускает прежнее приложение, которое перезапускает демон.

`NSIS_HOOK_PREINSTALL` останавливает работающий `unisond.exe` до того, как установщик распакует файлы,
потому что демон держит свой бинарник. Приложение останавливает демон до запуска помощника, а хук -
страховка для установки, где он все еще работает.

Обновление из приложения доступно только в release-сборках x86_64; dev-сборка сообщает, почему не
может заменить себя. Rust-клиент пишет установщик без потока `Zone.Identifier`, поэтому Windows не
ставит метку Mark-of-the-Web; проверка подписи и хеша - единственный допуск к запуску.

### Подпись

Отпечаток сертификата Authenticode берется из окружения и никогда не сохраняется:

```sh
set UNISON_WINDOWS_CERT_THUMBPRINT=...
just package-windows
```

`UNISON_WINDOWS_TIMESTAMP_URL` задает сервер меток времени и по умолчанию равен
`http://timestamp.digicert.com`. Без отпечатка установщик и демон неподписаны: Windows показывает
неизвестного издателя, а SmartScreen предупреждает о скачанном установщике, пока у него не наберется
достаточно репутации.

`just verify-windows [path]` проверяет установщик, подсистему демона и, когда приложение
установлено, каталог установки, запись автозапуска и правило брандмауэра. Он печатает проверки,
которые нужны пользователю: повторный вход, буфер обмена между двумя устройствами, диалог
брандмауэра и удаление.

## Windows и остальное ядро

Буфер обмена Windows и хранилище ключей на DPAPI - единственные части, специфичные для платформы, и
обе собираются без cgo. Обнаружение, транспорт, сессия, blob-хранилище и локальный API - тот же
код, что и на macOS, поэтому демон Windows кросс-компилируется с любого хоста командой
`just build-unisond windows amd64`.

## Текущее состояние

Десктопное приложение и демон Windows упаковываются вместе, и установщик проверяется
`just verify-windows`, но Windows пока не релизная платформа: интеграционные тесты буфера обмена и
поток установщика идут только на Windows, а обычный набор тестов другого хоста их не покрывает.
