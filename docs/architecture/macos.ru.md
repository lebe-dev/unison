# macOS

Русский | [English](macos.md)

На macOS демон и есть устройство: он работает как `unisond` из сборки приложения, держит элементы
Keychain, следит за pasteboard и отдает локальный API на unix-сокете. Десктопное приложение - его
клиент.

```
Unison.app
  Contents/MacOS/Unison                 Tauri shell, the window
  Contents/MacOS/unisond                the daemon, universal binary
  Contents/Library/LaunchAgents/        the login item of the daemon
  Contents/PlugIns/UnisonShare.appex    the Share menu extension
  Contents/Resources/                   the frontend
```

## Порты платформы

`platform/darwin` дает два из четырех портов. Оба используют cgo, поэтому демон, который
предназначен для работы, собирается с `CGO_ENABLED=1`.

### Хранилище ключей

`platform/darwin/keystore` хранит каждый секрет как элемент generic password в Keychain:

- сервис определяет приложение, а аккаунт - это имя секрета;
- элементы читаемы после первой разблокировки сессии входа, никогда не покидают устройство и не
  синхронизируются в iCloud;
- ключница определяется при первом обращении - ключница по умолчанию процесса или ключница входа
  пользователя - и называется в каждом запросе, поэтому API никогда не ищет свою ключницу и не
  поднимает диалог с просьбой о ней.

| Сервис | Каталог данных |
|---------|----------------|
| `app.unison` | каталог данных по умолчанию |
| `app.unison.dev.<slug>-<hash>` | любой другой каталог данных |

Slug - это строчные буквы, цифры и одиночные дефисы, урезанные до 24 символов, а хеш пути различает
каталоги с одинаковым именем. Каталог всегда отображается в одно и то же имя, поэтому повторные
запуски правят те же элементы, а не добавляют новые под новым именем.

Без cgo операции возвращают `ErrUnsupported`; сборка, которая не может открыть ключницу,
возвращает `ErrNoKeychain`, и демон выходит с этой ошибкой. Интеграционные тесты используют
фиксированные сервисы `app.unison.test.keychain` и `app.unison.test.isolation` под build-тегом
`keychaintest`, поэтому `just test` никогда не трогает Keychain.

### Буфер обмена

`platform/darwin/clipboard` реализует pasteboard. У pasteboard нет уведомления об изменении,
поэтому наблюдатель опрашивает счетчик изменений каждые 300 мс.

- читаются текст, HTML, PNG-изображение и URL файлов каждого элемента;
- скриншот предлагает и `public.png`, и `public.tiff`: PNG берется как есть, а один только TIFF
  конвертируется в PNG в пределах лимитов изображений конвейера;
- скопированный файл приходит как свой путь, поэтому копирование большого файла здесь его не
  читает;
- каталоги пропускаются;
- содержимое с `org.nspasteboard.ConcealedType`, `TransientType` или `AutoGeneratedType`
  сообщается как чувствительное, и его полезная нагрузка никогда не читается;
- собственные записи несут `app.unison.origin`, поэтому конвейер их игнорирует.

`AccessBehavior` сообщает системную политику программного чтения, и `unisond` пишет предупреждение
при старте, когда чтения могут показать предупреждение или быть отклонены. Интеграционные тесты
pasteboard находятся под build-тегом `pasteboardtest` и возвращают содержимое буфера обмена по
окончании.

## Демон

`just build-unisond-host` собирает демон для хоста с cgo и Keychain. На macOS голый демон,
запущенный из терминала, принадлежит терминалу по разрешению на локальную сеть, и macOS отказывает
ему в локальной сети, даже когда разрешение есть у терминала. Поэтому сборка для хоста - это
бандл `bin/unisond.app` с идентификатором `app.unison.unisond.dev`, а `bin/unisond` - ссылка на
его бинарник. `just run-daemon` запускает этот бандл через LaunchServices.

Бандл держит одну идентичность между пересборками:

- фиксированный UUID Mach-O;
- подпись первой идентичностью `Apple Development` из ключницы или `UNISON_DEV_SIGN_IDENTITY`,
  когда она задана;
- регистрация в LaunchServices.

Без идентичности бандл подписывается ad-hoc, и Keychain спрашивает после каждой сборки.

Демон принимает `--data-dir`, `--endpoint`, `--clipboard`, `--name`, `--log-level` и
`--log-stderr`, а каталог данных по умолчанию - `~/Library/Application Support/Unison`. См.
[Демон и локальный API](local-api.ru.md#команда).

## Упаковка

`just package-macos` собирает приложение с демоном внутри, подписывает оба и пишет
`packaging/macos/build/Unison.app` и `packaging/macos/build/Unison-<version>.dmg`. Версия берется
из файла `VERSION` для бандла, образа диска и демона.

Демон - универсальный бинарник arm64 и x86_64, потому что он использует cgo для Keychain и
pasteboard и оба слайса собираются на macOS и сливаются через `lipo`. Приложение собирается под
архитектуру хоста; `just package-macos --universal` собирает универсальным и его.

### Элемент входа

`Contents/Library/LaunchAgents/app.unison.unisond.plist` делает демон элементом входа бандла:
`BundleProgram` указывает на `Contents/MacOS/unisond`, задача стартует при входе в систему, а
launchd перезапускает ее после падения.

Приложение регистрирует элемент входа через `SMAppService` при первом запуске упакованной сборки, а
переключатель в экране настроек регистрирует и снимает его потом. Система, которая требует
подтверждения, сообщает `requires-approval`, пока пользователь не разрешит элемент. Когда элемент
входа выключен, приложение запускает демон из бандла на остаток сессии.

`--login-item=status`, `--login-item=register` и `--login-item=unregister` меняют элемент входа из
командной строки - так проверяется упакованное приложение без окна. Элементу входа нужна подпись,
выданная Apple: ad-hoc сборка может его зарегистрировать, но launchd затем откажется запускать
задачу с кодом выхода 78.

### Info.plist и entitlements

Info.plist объявляет `NSLocalNetworkUsageDescription` и `NSBonjourServices` с `_unison._udp`,
`_unison-pair._udp` и `_unison-friends._udp`, потому что обнаружением занимается демон из бандла.

Бандл подписан с hardened runtime и entitlements из `desktop/src-tauri/entitlements.plist`: сетевой
клиент для спаренных устройств и локального API, сетевой сервер для слушателя QUIC.

### Подпись и нотаризация

Учетные данные берутся из окружения и никогда не сохраняются:

```sh
export UNISON_MACOS_SIGN_IDENTITY="Developer ID Application: Name (TEAMID)"
xcrun notarytool store-credentials unison-notary --apple-id you@example.com --team-id TEAMID
export UNISON_MACOS_NOTARY_PROFILE=unison-notary
just package-macos
```

`UNISON_MACOS_APPLE_ID`, `UNISON_MACOS_APPLE_PASSWORD` и `UNISON_MACOS_TEAM_ID` нотаризуют прямо
через аккаунт, а не через профиль ключницы. `UNISON_MACOS_SKIP_NOTARIZE=1` останавливается после
подписи, а `--no-dmg` собирает только приложение. Без `UNISON_MACOS_SIGN_IDENTITY` приложение
подписывается ad-hoc, чего достаточно для сборки и запуска бандла на машине сборки, но не для
распространения.

Демон подписан под `app.unison.unisond`, и элементы Keychain принадлежат этой идентичности. Смена
идентичности подписи заставляет macOS запросить доступ к существующим элементам, а ad-hoc
пересборка меняет его при каждой сборке. Держите идентификатор и сертификат стабильными между
релизами.

`just verify-macos [path]` проверяет компоновку, plist элемента входа, ключи Info.plist,
entitlements, hardened runtime и подпись, а также печатает проверки, которым нужна вторая машина:
запрос доступа к локальной сети, демон после повторного входа и буфер обмена между двумя
устройствами.

## Меню «Поделиться»

`Contents/PlugIns/UnisonShare.appex` добавляет Unison в меню «Поделиться» любого приложения для
файлов. Расширение написано на Swift и лежит в `desktop/share-extension`; `just package-macos`
собирает его через `swiftc`, для хоста или для обеих архитектур, как и приложение, и подписывает
его раньше приложения.

- Точка расширения `com.apple.share-services`, правило активации принимает до 32 файлов, предел
  одного предложения. Текст и ссылки не принимаются.
- Расширение обязано работать в песочнице, поэтому к демону не обращается. Оно открывает file URL
  общих файлов приложением своего бандла и завершает запрос.
- Launch Services открывает файл только приложением, которое заявляет его тип, поэтому `Info.plist`
  приложения объявляет `public.data` в `CFBundleDocumentTypes` с рангом `None`: Unison принимает
  любой файл, но не становится приложением для него по умолчанию.
- Приложение получает их как запрос на открытие (`RunEvent::Opened`), оставляет пути обычных
  файлов, а каталоги и прочие URL отбрасывает. Пути ждут во входящих оболочки, пока окно не заберет
  их через `take_shared_files`, так что общий доступ, который запустил приложение, не теряется,
  пока страница загружается.
- Окно открывает экран передач с выбранными файлами и отмеченными устройствами в сети, и
  пользователь отправляет предложение оттуда.

Расширению нужна настоящая подпись: macOS может скрыть подписанное ad-hoc. Новое расширение может
быть выключено в меню «Поделиться», пока пользователь не включит его в списке «Изменить
расширения» или в настройках расширений. `pluginkit -m -v -i app.unison.share` показывает, знает ли
система расширение, а `pluginkit -a <path>/UnisonShare.appex` регистрирует сборку вне
«Программ».

`yarn tauri dev` и `just desktop-build` собирают приложение без расширения.

## Имя устройства

Имя устройства приходит из локального API и хранится в настройке `device.name`. Без сохраненного
имени демон использует имя хоста, `--name` переопределяет его на один запуск, а переименование из
приложения меняет его для следующего старта.
