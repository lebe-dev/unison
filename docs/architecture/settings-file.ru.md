# Файл настроек

Русский | [English](settings-file.md)

Файл настроек - это документ JSON, который несет настройки устройства, чтобы пользователь мог их
сохранить и восстановить на этом или на другом устройстве. Демон пишет и читает свою часть, а
приложение добавляет в тот же документ свои локальные настройки. Имя файла содержит платформу и
время экспорта: `unison-<platform>-YYYYMMDD-HHMMSS.json`, где платформа - `macos`, `windows`,
`linux` или `android`, а время - UTC.

Формат принадлежит `core/settingsfile`, документ передают `ExportSettings` и `ImportSettings`
локального API, а показывают его пользователю CLI, десктопное приложение и приложение Android.

## Документ

```json
{
  "schema": "unison-settings",
  "format_version": 1,
  "exported_at": "2026-11-24T10:20:30Z",
  "platform": "macos",
  "app_version": "0.2.0",
  "core": {
    "require_confirmation": false,
    "require_file_confirmation": false,
    "allow_remote_settings": true,
    "blob_max_size_bytes": 1073741824,
    "strip_tracking": true,
    "sentry_enabled": false,
    "journal_enabled": false,
    "history_ttl": { "text": 604800, "image": 259200, "files": 86400 },
    "policy": {
      "relay_max_size_bytes": 1048576,
      "unmetered": {
        "relay": true,
        "text": { "action": "auto", "max_size_bytes": 10485760 },
        "image": { "action": "auto", "max_size_bytes": 10485760 },
        "files": { "action": "metadata", "max_size_bytes": 0 }
      }
    }
  },
  "app": {
    "desktop": {
      "theme": "dark",
      "login_item": true,
      "updates": { "enabled": false, "beta_channel": false, "interval": "daily" }
    },
    "android": {
      "operating_mode": "wifi_only",
      "updates": { "enabled": false, "beta_channel": false, "interval": "daily" }
    }
  }
}
```

Часть `core` - это настройки демона: флаги подтверждения, лимит blob-хранилища, параметры
отслеживания, согласие на отправку ошибок, журнал приложения, сроки жизни истории и сетевая
политика. Она пишется с действующими значениями, поэтому восстановление повторяет устройство.
Часть `app` держит локальные настройки клиента, по объекту на семейство платформ, и демон
сохраняет ее, не разбирая.

Объекты `app.desktop.updates` и `app.android.updates` несут одно и то же поведение обновлений:
включены ли фоновые проверки, включен ли бета-канал и интервал `six_hours`, `daily` или `weekly`. В
них нет установленной версии, загрузки и ключа подписи, поэтому восстановление меняет только выбор
пользователя.

Следующих значений в файле нет намеренно:

| Значение | Почему |
|----------|--------|
| имя устройства | оно идентифицирует это устройство, и восстановленный файл дал бы двум устройствам одно имя |
| каталог загрузок | это путь этого устройства |
| доступ к ретранслятору | он принадлежит группе, а токен - секрет, который API никогда не возвращает |
| спаренные устройства, история, буфер обмена | это не настройки, и файл нес бы идентичности и содержимое |

## Импорт

Импорт частичный: ключ, которого нет в документе, сохраняет записанное значение. Поэтому остаются
пригодными файл, отредактированный вручную, и файл с другой платформы, а импорт не стирает
настройку, о которой файл ничего не знает. Значения проверяются до записи, поэтому файл с
недопустимым лимитом или действием ничего не меняет.

Клиент применяет свою часть `app` и пропускает остальные, так что один файл восстанавливает и
десктоп, и устройство Android. Десктоп применяет тему, элемент входа и настройки обновлений,
Android - режим работы службы, категории уведомлений и настройки обновлений.

## Версии

`format_version` - версия формата, которой был записан файл. Эта версия приложения пишет версию 1.

- Старый файл читает более новое приложение через миграции `core/settingsfile`, по шагу на версию.
  Каждый шаг превращает разобранный документ предыдущей версии в текущий.
- Файл без `format_version` считается файлом текущей версии, поэтому файл, написанный вручную,
  остается пригодным.
- Файл более новой версии применяется теми ключами, которые знает эта версия. Импорт сообщает о
  более новой версии, и пользователю говорят, что для остального нужно обновить приложение.
- Неизвестный этой версии ключ пропускается и сообщается в точечной форме, например
  `core.future_setting`, поэтому документ может нести экспериментальную настройку, не ломая старое
  приложение.
- Файл с другой схемой отклоняется, как и файл больше 512 KiB.

Поэтому новую настройку достаточно добавить в структуру и в список известных ключей: старые
приложения ее пропустят, а будущая версия сможет перенести значение шагом миграции. Шаги лежат в
`core/settingsfile`.

## Клиенты

| Клиент | Экспорт | Импорт |
|--------|---------|--------|
| CLI | `unison settings export [path]` пишет файл или печатает документ без пути | `unison settings import <path\|->` применяет файл или стандартный ввод |
| Десктоп | Настройки > Общие > Файл настроек > Экспорт открывает диалог сохранения | Импорт открывает диалог выбора файла, применяет документ и локальные настройки |
| Android | Настройки > Файл настроек > Экспорт открывает системный выбор файла | Импорт читает выбранный файл, применяет документ и локальные настройки |

Оболочка десктопа пишет и читает выбранный файл через `settings_write` и `settings_read`;
приложение Android использует системный выбор документа, поэтому ни тому, ни другому не нужно
разрешение на доступ к хранилищу.
