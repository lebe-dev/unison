# Ретранслятор

Русский | [English](relay.md)

Ретранслятор соединяет устройства, которые не находятся в одной локальной сети. Он пересылает
непрозрачные датаграммы между участниками почтового ящика, поэтому два устройства по-прежнему
проводят свое QUIC-соединение с mutual TLS и гибридным обменом ключами внутри датаграмм
ретранслятора. Ретранслятор не видит ни ключей, ни открытого текста, ничего не держит на диске и не
узнает идентичность устройства.

В репозитории живут две части:

| Часть | Путь | Бинарник |
|------|------|--------|
| Клиент | `core/relay` | часть `unisond` и мобильного ядра |
| Сервер | `internal/relay`, `cmd/unison-relay` | `unison-relay` |

Клиент - это библиотека, а не процесс: узел открывает одно соединение с ретранслятором на
устройство и везет по нему почтовые ящики всех своих пар.

## Клиент

`core/relay` превращает ретранслятор в виртуальное пакетное соединение, поэтому транспорт не знает,
что его пакеты едут через ретранслятор.

```
peer session
  core/transport      QUIC over a net.PacketConn
    core/relay.Conn   one mailbox, one pair
      Dialer          one connection to the relay, many mailboxes
        quicCarrier   QUIC datagrams, primary
        wsCarrier     WebSocket over TLS, fallback
```

| Константа | Значение |
|----------|-------|
| ALPN и подпротокол | `unison-relay/1` |
| Путь WebSocket | `/relay` |
| Порт по умолчанию | 443 |
| Таймаут дозвона | 3 с |
| Задержка переподключения | 1 с, удваивается до 30 с |
| Очередь на пару | 256 датаграмм |
| Окно перехода | 30 минут до полуночи UTC |
| ID почтового ящика | 16 байт |

### Почтовые ящики

Оба устройства пары выводят один и тот же почтовый ящик из своего общего ключа рандеву и дня UTC:

```
mailbox = BLAKE3(rendezvous_key || uint64_be(day))[:16]
```

Пара, которая спарилась напрямую, договорилась о ключе рандеву во время спаривания. Два устройства
Personal, которые знают друг друга через группу, выводят его из токена ретранслятора группы и обоих
ID устройств, поэтому одни только ID устройств ящик не раскрывают. ID меняется каждый день и ничего
не говорит о паре, поэтому ретранслятор не может следить за устройством через дни.

`Mailboxes` возвращает текущий день и, в последние 30 минут дня, еще и следующий. В полночь UTC
клиент закрывает соединение, переподключается без задержки и регистрирует новый набор.

### Соединение

`Dialer.Run` держит одно соединение с ретранслятором:

1. собрать почтовые ящики каждой открытой пары, не больше 256;
2. дозвониться по QUIC и откатиться на WebSocket, если попытка QUIC не удалась за 3 с;
3. отправить `Register` с токеном и ID ящиков, прочитать `RegisterResult` с лимитами;
4. обслуживать датаграммы, пока жив носитель;
5. переподключаться сразу при переходе или смене набора ящиков и с задержкой во всех остальных
   случаях.

Предпочтение WebSocket залипает между переподключениями, пока `NetworkChanged` его не сбросит,
поэтому сеть, которая блокирует UDP, не повторяет QUIC на каждой попытке.

`Conn` реализует `net.PacketConn` для одной пары. Его адрес имеет сеть `relay` и имя вида
`relay:N`, так узел сообщает путь пира. Ретранслятор не несет адрес пира, поэтому локальный и
удаленный адреса совпадают. Запись, пока ретранслятор недоступен, отбрасывается и завершается
успешно, как пакет на сломанном канале; QUIC его переповторит. Входящая очередь ограничена, и
излишек отбрасывается.

### Размер пакета

Датаграмма ретранслятора едет в одном QUIC-пакете соединения с ретранслятором, а он 1280 байт,
поэтому один кадр несет не больше 1240 байт. Кадр добавляет 24 байта заголовков при пустой полезной
нагрузке.

Внутреннее QUIC-соединение должно в это поместиться, а рукопожатию нужно 1200 байт. `PacketSize`
возвращает самый большой внутренний пакет, который помещается; он возвращает ноль, когда
датаграммы слишком малы, и тогда узел отказывается от пути через ретранслятор и пишет
предупреждение в лог. При `max_datagram_bytes` по умолчанию 1400 размер внутреннего пакета - 1216,
и обнаружение MTU пути для этого соединения выключено.

### Когда узел использует ретранслятор

Локальная сеть всегда выигрывает:

1. узел пробует ручной, обнаруженный и кешированный адреса;
2. когда пир остается офлайн `RelayDelay` (3 с) и сетевая политика разрешает ретранслятор, по одной
   горутине на пару открывает путь через ретранслятор;
3. пока пара онлайн через ретранслятор, узел продолжает дозваниваться по локальным адресам;
4. как только локальное соединение установлено, оно перехватывает работу, а путь через ретранслятор
   закрывается.

Клиент ретранслятора также останавливается, когда группа выключает ретранслятор, и соединения на
пути через ретранслятор в этот момент закрываются.

Сессия переживает недоступность ретранслятора `RelayGrace` (15 с): QUIC переповторяет пакеты, когда
ретранслятор возвращается. Более долгая недоступность завершает сессию, и она открывается снова,
когда ретранслятор появляется.

Настройки принадлежат группе Personal: адрес и один токен доступа, сохраненные запечатанными и
распространяемые с данными группы. Адрес - это хост и порт с необязательной схемой `https://` или
`wss://`. После сохранения токен не возвращает никто; клиенты узнают только, задан ли он.

## Сервер

`internal/relay` - это сервер. У него нет состояния на диске и нет идентичностей: клиент
аутентифицируется токеном доступа, а почтовый ящик - это набор соединений с общим ID.

| Файл пакета | Ответственность |
|--------------|----------------|
| `server.go` | сервер, емкость, регистрация, пересылка, цикл записи пира |
| `quic.go` | слушатель UDP, регистрация на соединение, цикл датаграмм |
| `ws.go` | слушатель TLS, upgrade до WebSocket, ping |
| `registry.go` | почтовые ящики в памяти |
| `limits.go` | хеши токенов, частота и квота |
| `frame.go` | кадрирование и управляющие кадры |
| `http.go` | `/healthz`, `/readyz`, `/metrics` |
| `metrics.go` | счетчики и их отрисовка для Prometheus |

### Регистрация

Первое сообщение соединения - `Register` с токеном и ID ящиков. Сервер сравнивает SHA-256
предъявленного токена с каждым сконфигурированным хешем за постоянное время, проверяет, что ID не
больше `max_mailboxes` и каждый по 16 байт, и входит в ящики. Он отвечает `RegisterResult`,
который всегда несет блок лимитов, затем закрывает поток регистрации или заканчивает фазу
регистрации WebSocket.

| Статус | Смысл |
|--------|---------|
| `OK` | зарегистрирован |
| `UNAUTHORIZED` | неизвестный или пустой токен |
| `QUOTA_EXCEEDED` | токен израсходовал свой трафик |
| `INVALID_ARGUMENT` | искаженная регистрация или ID ящика |
| `UNAVAILABLE` | сервер на пределе емкости |
| `DATAGRAMS_REQUIRED` | транспорт не может нести ненадежные сообщения |
| `SHUTTING_DOWN` | сервер останавливается |

На QUIC коды отображаются в коды ошибок приложения `0x01`-`0x06`; на WebSocket - в коды закрытия
`4000 + status`.

### Почтовые ящики

Ящик существует, пока хотя бы одно соединение является его участником. В один ящик помещается
четыре участника; пятый вход вытесняет самого старого, поэтому переподключающийся клиент
выигрывает у устаревшего соединения. `max_mailboxes_total` ограничивает реестр.

Датаграмма пересылается байт в байт каждому другому участнику своего ящика. Сервер проверяет, что
отправитель участник, что полезная нагрузка не пуста и не превышает размер и что у токена остались
частота и квота. Он никогда не переписывает и не проверяет полезную нагрузку.

| Причина отбрасывания | Смысл |
|-------------|---------|
| `malformed` | не кадр датаграммы или ID ящика не 16 байт |
| `too_large` | полезная нагрузка больше `max_datagram_bytes` |
| `not_member` | отправитель не входил в ящик |
| `rate_limit` | токен превысил свою частоту |
| `no_peer` | отправитель один в ящике |
| `backpressure` | очередь цели заполнена |
| `write` | запись цели не удалась |

Датаграмма сверх частоты отбрасывается, а соединение остается. Токен, у которого кончилась
квота, закрывается с `QUOTA_EXCEEDED`. Трафиком считаются только принятые датаграммы.

### Лимиты

| Флаг | Переменная окружения | По умолчанию |
|------|-------------|---------|
| `-quic-addr` | `UNISON_RELAY_QUIC_ADDR` | `:8443`, `:443` в образе |
| `-ws-addr` | `UNISON_RELAY_WS_ADDR` | `:8443`, `:443` в образе |
| `-http-addr` | `UNISON_RELAY_HTTP_ADDR` | `:8080` |
| `-tls-cert`, `-tls-key` | `UNISON_RELAY_TLS_CERT`, `UNISON_RELAY_TLS_KEY` | обязательны |
| `-tokens` | `UNISON_RELAY_TOKENS` | нет |
| `-tokens-file` | `UNISON_RELAY_TOKENS_FILE` | нет |
| `-log-level` | `UNISON_RELAY_LOG_LEVEL` | `info` |
| `-max-mailboxes` | `UNISON_RELAY_MAX_MAILBOXES` | 8 на соединение |
| `-max-datagram-bytes` | `UNISON_RELAY_MAX_DATAGRAM_BYTES` | 1400 |
| `-rate`, `-rate-burst` | `UNISON_RELAY_RATE`, `UNISON_RELAY_RATE_BURST` | 200 в секунду, всплеск 400 |
| `-quota-bytes`, `-quota-window` | `UNISON_RELAY_QUOTA_BYTES`, `UNISON_RELAY_QUOTA_WINDOW` | 1 GiB за 24 часа |
| `-max-connections` | `UNISON_RELAY_MAX_CONNECTIONS` | 4096 |
| `-max-mailboxes-total` | `UNISON_RELAY_MAX_MAILBOXES_TOTAL` | 100000 |
| `-ping-interval` | `UNISON_RELAY_PING_INTERVAL` | 30 с |
| `-register-timeout` | `UNISON_RELAY_REGISTER_TIMEOUT` | 10 с |

Окружение задает значения по умолчанию, а флаги их переопределяют. Токены берутся из файла по
одному на строку или из переменной через запятую; файл допускает комментарии и пустые строки.
Сервер держит только SHA-256 каждого токена.

### Здоровье и метрики

`/healthz` сообщает о процессе, `/readyz` сообщает, что новые соединения принимаются, а `/metrics`
отдает формат Prometheus по простому HTTP для съема сайдкаром.

Метрики покрывают соединения и регистрации по транспорту, живые почтовые ящики, датаграммы и байты
по направлениям, uptime и отброшенные датаграммы по причинам. Метки никогда не несут ящики, токены,
адреса или ID устройств. Логи - это JSON в stderr, и они никогда не несут полезные нагрузки, токены
или ID ящиков.

### Жизненный цикл

`Start` загружает сертификат, ключ и токены, затем привязывает QUIC, WebSocket и HTTP. `Close`
помечает сервер закрытым, чтобы `/readyz` падал, шлет `Close` каждому пиру, покидает ящики и
закрывает слушатели и сокеты. `cmd/unison-relay` отображает `SIGINT` и `SIGTERM` в это.

Обслуживать группу может только один экземпляр: ящики живут в памяти, поэтому вторая реплика
держит несовпадающий реестр, а перезапуск по одному роняет все соединения.

## Развертывание

`deploy/relay` держит образ и compose-файл. Образ собирается из `scratch`: два статических
бинарника, без шелла, без пакетного менеджера, и процесс работает под uid 10001, поэтому корневая
файловая система может оставаться только для чтения.

| Порт | Протокол | Назначение |
|------|----------|---------|
| 443 | UDP | QUIC, основной транспорт |
| 443 | TCP | WebSocket по TLS, откат для сетей, блокирующих UDP |
| 8080 | TCP | здоровье и метрики, простой HTTP, только loopback |

QUIC - это UDP, и обычный HTTP ingress или обратный прокси его не маршрутизируют: публикуйте UDP
порт на хосте, где работает ретранслятор, или ставьте перед ним балансировщик уровня 4. Откат на
WebSocket - это обычный TLS по TCP и проходит через ingress, у которого включены upgrade.

Compose-файл монтирует `deploy/relay/secrets` только для чтения с `cert.pem`, `key.pem` и
`tokens.txt`, сбрасывает все возможности и ставит `no-new-privileges`. Файлы должны быть читаемы
для uid 10001.

## Свойства безопасности

Что ретранслятор может наблюдать: адреса клиентов, TLS SNI и тайминги, предъявленный токен, ID
ящиков, в которые входит соединение, размеры и частоту датаграмм. Он может понять, что два
соединения делят ящик в один день и что устройства делят токен.

Чего он наблюдать не может: открытый текст полезной нагрузки, ключи, идентичности устройств и
связь между парой через дни. Внутреннее соединение держит свои TLS 1.3, гибридный обмен ключами,
проверку сертификата и доказательство аутентификации сессии, поэтому ретранслятор - это транспорт,
который видит шифртекст.

Без ID ящика клиент не может получать трафик пары даже с валидным токеном, а ID ящика - это
128-битный хеш, который нельзя перебрать.
